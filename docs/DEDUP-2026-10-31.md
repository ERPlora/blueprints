# Copias quitadas y nombres que engañaban (2026-10-31)

La librería tenía **476 WebP pero solo 278 dibujos distintos**: 275 ficheros eran, byte a byte, el mismo
fichero que otro (77 grupos, comprobado con el SHA de cada fichero). Por carpeta: `fitness/` 20 de 20 (los 20
ficheros eran la misma tarjeta de socio con una pesa), `hospitality/` 218 de 277 (12 sushis iguales, 8 tés
iguales, 7 pastas y ramen iguales…), `beauty_body/` 16 de 35, `wellness_spa/` 11 de 18, `beauty_hair/` 8 de 43 y
`retail/` 2 de 83. Entró así desde el repo viejo (2026-07-19): las imágenes «de verdad» de esos productos no
existieron nunca. El manifiesto lo tapaba a medias: `fitness/clase_yoga` se titulaba «Clase de yoga» y era la
tarjeta de socio, y el README documentaba la reutilización en vez de prohibirla.

La IA del Hub busca imágenes por nombre y título: un nombre engañoso le hace proponer una tarjeta de socio para
«yoga». Ioan decidió: **un dibujo = un fichero, y todo nombre de fichero describe lo que se ve** (README, «Un
dibujo, un nombre»).

## Qué se hizo

- De cada grupo queda **un fichero**, con el nombre que describe el dibujo (visto, no deducido del nombre); se
  borran las otras 198 copias y sus entradas de `img/catalog.json`. Si ningún nombre del grupo describía el
  dibujo, el que queda se renombra (7 grupos).
- Se renombran además 12 imágenes únicas cuyo nombre ya engañaba (el manifiesto lo
  decía en el título: `retail/zanahorias_kg` era «Tarta de zanahoria») o nombraba una marca.
- Resultado: **278 ficheros, 278 dibujos**, una entrada por fichero, cada título dice lo que se ve.
- Para que no vuelva: `scripts/catalog.py validate` falla si dos WebP de `img/` son idénticos byte a byte y lista
  cada grupo (`same drawing under N names: …`); lo corre la CI (`validate.yml`) en cada PR y en cada push a
  `main`. Las imágenes parecidas pero no idénticas no las caza (queda fuera).

## Lo que esto toca fuera de este repo

- **Semillas del Hub** (`base/seeds/*.json` de `ERPlora/hub`, que se validan contra este manifiesto en su CI):
  `hospitality/hamburguesa_gourmet` (retirada) pasa a `hospitality/hamburguesa_clasica` en «Hamburguesa de la
  casa»; `beauty_hair/lavado_masaje` (renombrada) pasa a `beauty_hair/secado_cepillo` en «Peinado» / «Blow-dry»;
  `retail/patatas_kg` (renombrada a `hospitality/patatas_fritas_cucurucho`) se quita de «Patatas bravas», que se
  queda sin imagen: unas patatas fritas no son unas bravas. Va en una PR del Hub que se mergea **después** de esta.
- **Hubs en producción**: el Hub solo sirve lo que nombra el manifiesto, así que un producto que ya apuntara a un
  nombre retirado se queda sin imagen (no se ha podido comprobar desde aquí si alguno lo hace).
- **El bucket**: `publish.yml` no borra. Las 217 imágenes que salen (198 copias y 19 nombres viejos) siguen en
  `s3://erplora-<entorno>-hubs/shared/catalog/` hasta la poda explícita:

```bash
gh workflow run publish.yml -R ERPlora/blueprints -f prune=true -f max_prune=220
```
